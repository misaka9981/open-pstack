### Opening a PR

Invoked at the end of every other playbook.

Work from a git worktree off trunk, and keep unrelated work out of it. To reuse one branch across worktrees, resolve and validate `<head-url>` through Shipping step 1, capture it as `head_url`, then run `git fetch -- "$head_url" "refs/heads/$branch" && git reset --hard FETCH_HEAD` between them. Rebase into small, landable commits. Run `/deslop` over the diff before commit.

Title: `type(scope): subject`, naming a real symbol when one carries the change. Body: a one-minute briefing under 40 lines with these `##` headings in order, dropping empty ones: `## Why`, `## What changed`, `## Scope`, `## Tradeoffs` (only rejected alternatives a reviewer would otherwise ask about), `## Blast Radius`, `## Verification`.

Stack follow-ups by base branch. Use `gh` by default, or `origin pr` when Origin's CLI resolves the repository, and pass `--repo "$base_repo"` to every `gh pr` command, with `<base-repo>` validated through the active forge. Open PRs ready: `gh pr create --repo "$base_repo"` without `--draft`, or `origin pr create --status open`. If repository instructions require a draft until named evidence exists, open the PR as a draft and mark it ready only after recording that evidence. When the head repository is a fork, every PR targets trunk in the base repository while stacked local branches keep parent ancestry, because a fork-only parent branch cannot be a PR base. Create every fork PR with the resolved Origin command, or on GitHub with `gh api --method POST "repos/$base_repo/pulls" -f "title=$title" -f "body=$body" -f "head=$fork_owner:$branch" -f "head_repo=$head_name" -f "base=$trunk" --jq .html_url`. Before rebasing, force-pushing, or retargeting an existing child, apply Shipping step 4's disarm-and-confirm rule to that child and every descendant. Opening a PR does not start a babysit.
