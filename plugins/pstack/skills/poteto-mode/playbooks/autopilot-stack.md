### Autopilot-stack

Run the Autopilot-full playbook, but do not merge.

1. **In place of step 5, stop at verified.** Stop when each PR is verified and green at its current head, then hand the PRs to the operator. After the handoff, nobody pushes without the operator's go. Every loop tick prompt names this file, so each tick sees the no-merge rule. The operator sends only the current bottom PR through Shipping, one at a time. Merge-when-ready applies only to that bottom, after Shipping has disarmed and confirmed every descendant, so never offer or arm it for a stack as a whole or for a descendant.
2. **Stack a PR only when it builds on another PR.** This is the one exception to step 3. Base the PR on the other PR's branch in place of trunk, per **Size and stacks** in `playbooks/opening-a-pr.md`. When the head and base repositories are the same, the PR targets its parent's branch. When the head repository is a fork, keep the local child branch rebased onto its parent's exact tip but create or retarget every PR against `<trunk>` in the base repository, because a forge cannot use a fork-only parent branch as a PR base. With GitHub, create it with `gh api --method POST "repos/$base_repo/pulls" -f "title=$title" -f "body=$body" -f "head=$fork_owner:$branch" -f "head_repo=$head_name" -f "base=$trunk" --jq .html_url`, as Opening a PR specifies. Record the bottom-to-top order, and for fork heads never infer stack order from their equal base branches.

   In place of step 2's rebase onto trunk, each PR's owner rebases it onto its parent PR's branch, and the stack root rebases onto trunk. Before you rebase, force-push, or retarget an existing PR, apply Shipping step 4's disarm-and-confirm rule to that PR and every descendant, stopping if the forge cannot confirm every request off. Fetch trunk through `<base-remote>`. Fetch another stack branch directly through `<head-url>`, because `<head-remote>` may have the base repository as its fetch URL and the fork as its push URL. Record the fetched target as `<parent-tip>`. Record the branch's published SHA as `<captured-sha>` with `git ls-remote -- "$head_url" "refs/heads/$branch"` and require it to equal the local pre-rebase tip. Require `git merge-base --is-ancestor "$current_base_sha" "refs/heads/$branch"` to pass. When the parent changed, move only the child's commits with `git rebase --onto "$parent_tip" "$current_base_sha" -- "$branch"`, then record `<parent-tip>` as the child's new patch base. Publish with `git push --force-with-lease="refs/heads/$branch:$captured_sha" -- "$head_url" "HEAD:refs/heads/$branch"`.

   A new head on the lower PR restacks the PRs above it, bottom-up, each through step 2's captured-SHA lease flow. A PR whose `git patch-id` over its recorded patch-base-to-head diff the restack leaves unchanged keeps its verdict.
