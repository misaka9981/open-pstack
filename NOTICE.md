## What changed in the port

The port is editorial, not mechanical. See [CHANGES.md](CHANGES.md) for the full per-skill audit of substitutions applied.

Summary of structural changes:

- Plugin content lives at `plugins/pstack/` (with its own `.claude-plugin/plugin.json`). The repo root holds `.claude-plugin/marketplace.json` and the LICENSE / NOTICE / README / CHANGES docs.
- `.claude-plugin/marketplace.json` added at repo root so the repo is installable via `/plugin marketplace add`. The marketplace's single plugin entry sources from `./plugins/pstack`.
- The native `plugins/pstack/skills/` tree is the only user-facing workflow surface. Claude Code and Codex invoke those skills directly.
- One skill imported from `cursor-team-kit`: `deslop`, copied verbatim. pstack routes to it from poteto-mode and its playbooks. Six other team-kit skills that pstack never referenced were removed in 1.5.6.
- `plugins/pstack/skills/babysit/` is independently authored as the Claude Code analog of Cursor's `/babysit` built-in. It has no upstream pstack equivalent; its workflow is informed by Cursor's public `/babysit` behavior. No code or prose was copied from any source.
- `plugins/pstack/skills/poteto-mode/scripts/` is vendored from upstream (`watch-pr`, `orch`, `bootstrap.ts`, `worktree-audit.sh`, `package.json`, `bun.lock`) with these port edits: `worktree-audit.sh` reads `~/.claude/projects/` instead of Cursor's transcript directory and warns when `jq` or `rg` is missing (their absence silently blanks the columns the prune decision reads), the private workspace package is named `@open-pstack/poteto-mode-tools`, `bootstrap.ts` rejects Node before it reads Bun-only APIs, and `package.json` includes the port-authored tests in `bun run test`. `check-plan.mjs` is the Cursor 0.14.3 checker adapted for the shared Claude Code and Codex skeleton, with upstream's fenced-code rules from `87c8103`. `bootstrap.test.ts` and `check-plan.test.ts` are authored for this port. The fenced-code cases in `check-plan.test.ts` come from upstream's `check-plan.test.ts` at `87c8103` and assert the port checker's own messages.
- `plugins/pstack/agents/comment-sicko.md` matches upstream. The port first renamed upstream's `Comment Sicko` agent to `comment-sicko` so the name works as a Claude Code `subagent_type`. Upstream adopted the same id in `de2dba6`.
- `plugins/pstack/agents/poteto-agent.md` keeps the upstream prompt, names `Agent` spawns instead of `Task` spawns, and adds Claude Code `skills` frontmatter so the isolated subagent preloads `pstack:poteto-mode`. With no path from its parent, it uses that preloaded copy instead of upstream's `~/.cursor/plugins/` search. Its description also names read-only investigation helpers, warns against `Explore`, and tells the parent to set a configured role's `model` and `effort` on the call.
- Claude-native Fable, Opus, Sonnet, and Haiku lanes are port-authored agent definitions. They select the rolling family alias plus requested effort for every selectable Claude-native pair in the provider-dispatch model matrix and additional Claude family table. Routed workflow skills dispatch them. A poteto-mode delegate uses `poteto-agent` instead.
- A Codex build shares the same `skills/` tree. It adds `plugins/pstack/.codex-plugin/plugin.json`, a root `.agents/plugins/marketplace.json`, and `plugins/pstack/skills/poteto-mode/references/codex-tools.md` (the Claude-to-Codex tool, model, and built-in map), plus a one-line Platform note in the skills that name a Claude primitive. The skill content itself is unchanged. See [CHANGES.md](CHANGES.md#codex-port).
